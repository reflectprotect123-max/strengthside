# Non-LLM AI and research crosswalk

## Decision

THE Hybrid System should be built as five specialist systems feeding one deterministic **Multi-model adaptive control system (MMACS)**. Engineering supplies the trustworthy control machine. Research supplies the meaning, evidence, parameters and permitted action bounds. Neither side can substitute for the other.

## Proposed model stack

| Layer | Initial implementation | Later candidate family | Research required before athlete use |
|---|---|---|---|
| Strength | Typed history, deterministic interpreters, bounded proposals | Robust exercise-specific time series; hierarchical/Bayesian personal response | Valid performance signals, measurement error, progression actions and bounds |
| Conditioning | Modality-specific event/state contracts | State-space and dynamic regression by modality | Intensity semantics, dose-response, device validity and interference |
| Nutrition | Intake/mass/missingness contracts | Dynamic energy-balance/state-space estimator | Expenditure model, trend/update logic, logging-quality gates and uncertainty |
| Recovery | Vector observations; separate pain/illness records | Multivariate state estimation and protocol-specific personal baselines | Measurement validity, protocol/freshness and predictive meaning; no universal readiness oracle |
| Coordinator | Deterministic schedule, goal, lock and continuity policy | Finite candidate optimization and versioned arbitration | Owned precedence, support/interference graph and any scientific trade-offs |
| MMACS | Trust gateway, state vector, bounded candidates, validators, abstention, receipt | Bounded personal residual models and robust constrained optimization | Valid latent states, targets, objectives, constraints, weights and calibration evidence |

The initial optimizer should select from a finite action set using lexicographic policy and deterministic tie-breaking. It should not use autonomous reinforcement learning, unconstrained online learning, an opaque neural controller or an LLM.

## What can still be built before scientific research is needed

The current package has the evidence store, search, provenance, promotion/refusal, runtime-artifact boundary, abstention, receipts, replay and basic synthetic fixtures. The remaining pre-research engineering scope is:

1. Synthetic five-system event generator.
2. Strict versioned domain contracts with freshness and compatibility checks.
3. Vector athlete-state assembler using synthetic semantics.
4. Bounded synthetic candidate generator.
5. Action-scoped locked-policy engine.
6. Deterministic conflict graph, arbitration trace and tie-break rules.
7. Finite candidate optimizer using explicitly synthetic placeholder objectives.
8. Property, fuzz, crash-recovery and million-record scale harnesses.
9. Evidence-to-feature and parameter-provenance contracts.
10. Frozen-dataset/model-card pipeline, shadow comparator and rollback dashboard.

That produces a full synthetic MMACS control loop with zero approved scientific models. Engineering must stop when a feature, coefficient, window, prior, action bound, interaction, objective or athlete-specific parameter needs scientific meaning.

## When research starts

Research starts at the first primary-source appraisal and becomes unavoidable before the first researched vertical slice. The software and research programmes can therefore run in parallel:

- Engineering finishes the synthetic control harness and research-integration contracts.
- Research performs corpus repair, freezes protocols and verifies measurement validity.
- They meet when one evidence-complete decision path enters offline testing.

No model waits for all five domains to be “finished.” Each bounded decision path earns its own progression from draft to offline, shadow and limited personal activation.

## Research depth

### Activation-grade portfolio

Across all five systems, the planning target is:

- 115–170 registered decision questions;
- 440–810 fully reviewed sources;
- 1,650–3,800 verified observations;
- 345–670 adjudicated claims;
- 86–145 frozen syntheses;
- 57–115 candidate rules/policies.

Counts are workload controls, not evidence by themselves. A narrow low-risk path can require less; a contentious path can require far more or remain unactivatable.

### Mature personal research platform

- 300–600 registered decision questions;
- 10,000–30,000 screened works;
- 2,500–6,000 included full-text sources;
- 15,000–40,000 verified observations;
- 1,500–4,000 adjudicated claims;
- 250–600 frozen syntheses;
- 200–800 product-behaviour fixtures;
- 100–300 released deterministic rules/policies;
- only a small identifiable set of active personal models.

Five to fifteen million raw text lines may exist for discovery, but they carry no runtime authority. Line count is a storage statistic; verified decision coverage is the quality measure.

## Scenario programme

There are 12 scenario families:

1. Normal single-system progression/maintenance.
2. Strength–Conditioning interference and support.
3. Training–Nutrition demand mismatch.
4. Recovery context versus performance evidence.
5. Three-to-five-system conflicts.
6. Missing, stale, incompatible or low-quality data.
7. Cold start and insufficient personal history.
8. Goal, phase, schedule, equipment and travel changes.
9. Heat, occupational load and environmental context.
10. Pain, illness and HRV locked-policy boundaries.
11. Drift, sensor/protocol changes and outliers.
12. Tampering, malformed inputs, lifecycle, rollback and replay.

| Gate | Scenario volume | Purpose |
|---|---:|---|
| First integrated release | At least 100 reviewed cross-system cases | Prove the complete five-system chain and locked policies |
| Serious pre-shadow suite | 650–1,200 hand-designed canonical cases | Cover normal, conflict, missingness, lifecycle and adversarial branches |
| Mature conflict catalogue | 500–2,000 reviewed cross-system conflict cases | Deep coverage of pairwise and higher-order interactions |
| Generated robustness suite | 10,000–100,000+ deterministic variants | Combinatorial, boundary, property and fuzz coverage |

Exhaustive enumeration is impossible. Use risk-based canonical cases, pairwise/t-wise combinations, boundary-value generation, property tests and personal historical replay.

## Staged programme

| Stage | Engineering output | Research output | Exit gate |
|---|---|---|---|
| 0 — current | Evidence operations, runtime trust boundary, abstention and replay | Discovery corpus only | Complete |
| 1 — synthetic control | Full deterministic MMACS loop on synthetic inputs | Protocol freeze and corpus repair | No unapproved artifact can act |
| 2 — integration contracts | Evidence/feature graph, model cards, offline and shadow harness | Measurement validity and safety-boundary reviews | Verified packages enter build plane without restructuring |
| 3 — first vertical slice | One narrow executable candidate | Complete source-to-claim-to-policy chain | Offline gates pass |
| 4 — shadow | Non-applying live comparator | Representative-case and applicability review | Predeclared shadow criteria pass |
| 5 — limited personal | One bounded reversible action family | Personal calibration evidence | No worse than baseline; immediate rollback |
| 6 — expansion | Additional slices and interactions | Updated syntheses and contradiction review | Each bundle earns activation independently |

## Recommended next move

Build the synthetic MMACS harness while beginning Research Wave 0 and Wave 1. Do not attempt all five scientific engines at once. Select one narrow decision question per system, but promote only the first vertical slice that has the cleanest data, shortest feedback loop, smallest reversible action and complete evidence chain.
